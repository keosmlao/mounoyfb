# FBMONOY — ລະບົບຈັດການການຍິງໂຄສະນາ Facebook

ຈັດການແຄມເປນ, ບັນທຶກຄ່າໂຄສະນາ ແລະ ຜົນລາຍວັນ, ຕິດຕາມລູກຄ້າທີ່ທັກເຂົ້າມາ
ແລະ ວັດຜົນເປັນເງິນກີບ (ROAS / ກຳໄລ / ຄ່າຕໍ່ 1 ຄົນທັກ).

ໃຊ້ງານໄດ້ເຕັມທີ່ດ້ວຍການປ້ອນມື — ບໍ່ຕ້ອງມີ Facebook API. ເມື່ອພ້ອມແລ້ວ
ຄ່ອຍໃສ່ access token ເພື່ອດຶງຂໍ້ມູນອັດຕະໂນມັດ.

## ຕິດຕັ້ງ

ຕ້ອງມີ Node 20+ ແລະ PostgreSQL ແລ່ນຢູ່.

```bash
# 1. ສ້າງຖານຂໍ້ມູນ
createdb fbmonoy

# 2. ຕັ້ງຄ່າ
cp .env.example .env      # ແກ້ DATABASE_URL ໃຫ້ຖືກກັບເຄື່ອງທ່ານ
#    ແລ້ວຕັ້ງລະຫັດຜ່ານເຂົ້າລະບົບ (ຈຳເປັນ):
#    APP_PASSWORD=ລະຫັດທີ່ທີມໃຊ້ຮ່ວມກັນ
#    SESSION_SECRET=$(openssl rand -base64 48)

# 3. ຕິດຕັ້ງ + ສ້າງຕາຕະລາງ
npm install
npm run db:migrate

# 4. ຕັ້ງຄ່າເລີ່ມຕົ້ນຂອງຮ້ານ (ຖານຂໍ້ມູນສະອາດ ພ້ອມໃຊ້ຈິງ)
npm run db:clear -- "ຊື່ຮ້ານຂອງທ່ານ"

#    ຫຼື ຖ້າຢາກເບິ່ງໜ້າຈໍດ້ວຍຂໍ້ມູນຕົວຢ່າງ 60 ວັນກ່ອນ:
#    npm run db:seed

# 5. ແລ່ນ
npm run dev
```

ເປີດ http://localhost:3000

> `db:clear` ແລະ `db:seed` **ລຶບຂໍ້ມູນທັງໝົດ** ກ່ອນ — ຢ່າແລ່ນໃສ່ຖານຂໍ້ມູນຈິງທີ່ໃຊ້ຢູ່.

## ວິທີໃຊ້ປະຈຳວັນ

1. ຕັ້ງ **ບັນຊີໂຄສະນາ**, **ເພຈ**, **ສິນຄ້າ** ໜຶ່ງເທື່ອຕອນເລີ່ມ
2. ສ້າງ **ແຄມເປນ** ແລ້ວຜູກກັບສິນຄ້າ (ຈຳເປັນ ຖ້າຢາກໃຫ້ຄິດ ROAS ໄດ້)
3. ທຸກເຊົ້າໄປໜ້າ **ບັນທຶກຜົນລາຍວັນ** → ເລືອກວັນ → ໃສ່ອັດຕາແລກປ່ຽນ →
   ພິມຄ່າໂຄສະນາ ແລະ ຜົນຂອງແຕ່ລະແຄມເປນ → ກົດ “ບັນທຶກທັງໝົດ”
4. ລູກຄ້າທີ່ທັກເຂົ້າມາ ໃສ່ຢູ່ໜ້າ **ລູກຄ້າ** ແລ້ວອັບເດດສະຖານະຈົນປິດການຂາຍ
5. ເບິ່ງຜົນຢູ່ໜ້າ **ໜ້າຫຼັກ** ແລະ **ລາຍງານ**

## ເລື່ອງເງິນ ແລະ ອັດຕາແລກປ່ຽນ

Facebook ຕັດເງິນເປັນ USD ແຕ່ຍອດຂາຍເປັນກີບ. ລະບົບຈຶ່ງເກັບ 2 ຄ່າ:

- `spend` — ຕາມສະກຸນຂອງບັນຊີໂຄສະນາ (ຄ່າທີ່ເຫັນໃນ Ads Manager)
- `spendLak` — ແປງເປັນກີບແລ້ວ (`spend × ອັດຕາແລກປ່ຽນຂອງວັນນັ້ນ`)

**ຕົວເລກທີ່ເອົາມາລວມ ແລະ ປຽບທຽບທັງໝົດໃຊ້ `spendLak`** ຈຶ່ງທຽບກັບຍອດຂາຍໄດ້ຖືກຕ້ອງ
ເຖິງວ່າອັດຕາແລກປ່ຽນຈະປ່ຽນທຸກວັນ. ອັດຕາທີ່ໃສ່ຕອນບັນທຶກຈະຖືກຈື່ໄວ້ໃນ
`ExchangeRate` ແລະ ຖືກໃຊ້ເປັນຄ່າຕັ້ງຕົ້ນເທື່ອຕໍ່ໄປ.

## ຕົວຊີ້ວັດຖືກຄິດແນວໃດ

ຄິດຈາກ**ຍອດລວມ**ຂອງຊ່ວງທີ່ເລືອກສະເໝີ (ບໍ່ແມ່ນຄ່າສະເລ່ຍຂອງອັດຕາສ່ວນລາຍວັນ
ຊຶ່ງຈະໃຫ້ຄຳຕອບຜິດ):

- CTR = ຄລິກ ÷ ຄັ້ງທີ່ເຫັນ
- CPC = ຄ່າໂຄສະນາ(ກີບ) ÷ ຄລິກ · CPM = ຄ່າໂຄສະນາ ÷ ຄັ້ງທີ່ເຫັນ × 1,000
- ຄ່າຕໍ່ 1 ຄົນທັກ = ຄ່າໂຄສະນາ ÷ ຈຳນວນຄົນທັກ
- ROAS = ຍອດຂາຍ ÷ ຄ່າໂຄສະນາ · ກຳໄລ = ຍອດຂາຍ − ຄ່າໂຄສະນາ

## ຫຼາຍລະດັບ ແລະ ການກັນນັບຊ້ຳ

ຕາຕະລາງ `Insight` ເກັບຜົນໄດ້ 3 ລະດັບ (ແຄມເປນ / ຊຸດ / ຊິ້ນ). ຖ້າບວກທຸກແຖວ
ຄ່າໂຄສະນາອັນດຽວກັນຈະຖືກນັບເຖິງ 3 ເທື່ອ. ລະບົບຈຶ່ງກຳນົດວ່າ:

- **ຍອດລວມທຸກບ່ອນ** (ໜ້າຫຼັກ, ລາຍການແຄມເປນ, ລາຍງານ, ການແຈ້ງເຕືອນ)
  **ນັບສະເພາະແຖວລະດັບແຄມເປນ**
- ແຖວລະດັບຊຸດ/ຊິ້ນ ເປັນ**ລາຍລະອຽດ** — ສະແດງໃນໜ້າແຄມເປນ ແລະ ໜ້າຊຸດເທົ່ານັ້ນ
- ການ sync ຈຶ່ງດຶງລະດັບແຄມເປນສະເໝີ ບໍ່ວ່າຈະຕິກລະດັບຍ່ອຍ ຫຼື ບໍ່

ກົດນີ້ຂຽນໄວ້ຢູ່ `src/lib/scope.ts` — ອ່ານກ່ອນຂຽນ query ໃໝ່ທີ່ບວກເລກ.

## ການວິເຄາະ ແລະ ຄຳແນະນຳ

ໜ້າ `/analysis` ຫັ່ນຜົນອອກເປັນ 4 ມິຕິທີ່ດຶງມາຈາກ Facebook ໂດຍກົງ
(ບໍ່ຕ້ອງພິມມືເລີຍ) ແລ້ວຈັດອັນດັບດ້ວຍ **ຄ່າຕໍ່ 1 ຄົນທັກ**:

| ມິຕິ | ຕອບຄຳຖາມ |
|---|---|
| ອາຍຸ + ເພດ | ຄົນກຸ່ມໃດທັກເຂົ້າມາຖືກທີ່ສຸດ |
| ບ່ອນວາງໂຄສະນາ | ໜ້າຟີດ / Reels / ສະຕໍຣີ ອັນໃດຄຸ້ມ |
| ແຂວງ | ຄົນແຂວງໃດຕອບຮັບດີ |
| ຊົ່ວໂມງ | ຍິງເວລາໃດຄົນທັກຫຼາຍ |

ຈາກນັ້ນ `src/lib/advice.ts` ປ່ຽນຕົວເລກເປັນຄຳແນະນຳ (ຄວນຕັດ / ຄວນເພີ່ມ /
ຄວນຍ້າຍ / ຄວນເຝົ້າເບິ່ງ) ພ້ອມ**ເຫດຜົນເປັນຕົວເລກ**ໃຫ້ກວດຄືນໄດ້ສະເໝີ.

**ເກນຄວາມໜ້າເຊື່ອຖື — ອ່ານກ່ອນປັບ.** ຂໍ້ມູນບາງໆບອກຫຍັງບໍ່ໄດ້ ລະບົບຈຶ່ງ
ໃຊ້ເກນຄົນລະຊຸດສຳລັບການບອກວ່າ "ດີ" ກັບ "ບໍ່ດີ":

- ຈະບອກວ່າກຸ່ມໃດ **ດີ** ຕ້ອງມີຄົນທັກ ≥ 10 ຄົນ **ແລະ** ≥ 5% ຂອງທັງໝົດ
- ຈະບອກວ່າກຸ່ມໃດ **ບໍ່ດີ** ໃຊ້ເກນຄົນທັກບໍ່ໄດ້ (ຄົນທັກນ້ອຍຄືຫຼັກຖານເອງ)
  ຈຶ່ງໃຊ້ເງິນທີ່ເສຍແທນ — ≥ 20,000 ກີບ ແລະ ≥ 5% ຂອງງົບ

ແຖວທີ່ຂໍ້ມູນຍັງບາງຖືກໝາຍວ່າ "ຂໍ້ມູນບາງ" ໃນຕາຕະລາງ.

> ⚠️ ຕົວເລກແຕ່ລະມິຕິຄືຄ່າໂຄສະນາອັນດຽວກັນທີ່ຫັ່ນຄົນລະແບບ — **ບວກຂ້າມມິຕິບໍ່ໄດ້**
> (ອາຍຸ + ແຂວງ = 2 ເທົ່າ). ເກັບແຍກຕາຕະລາງ `SegmentInsight` ຈຶ່ງບໍ່ກະທົບຍອດລວມ.

## ສະກຸນເງິນທີ່ສະແດງ

ຂໍ້ມູນເກັບເປັນ**ກີບສະເໝີ** ແຕ່ເລືອກໄດ້ວ່າຈະ**ສະແດງ**ເປັນກີບ ຫຼື ໂດລາ
(`/settings` → ສະກຸນເງິນທີ່ສະແດງ). ສະຫຼັບໄປມາໄດ້ທຸກເມື່ອໂດຍບໍ່ເສຍປະຫວັດ
ເພາະການແປງເກີດຕອນສະແດງເທົ່ານັ້ນ (`src/lib/money.ts`).

ເປັນຫຍັງບໍ່ເກັບເປັນໂດລາໄປເລີຍ: ຍອດຂາຍໃນລາວເປັນກີບ ແລະ ອັດຕາແລກປ່ຽນ
ປ່ຽນທຸກວັນ — ຖ້າເກັບເປັນໂດລາຈະທຽບຂ້າມວັນບໍ່ໄດ້.

## ການແຈ້ງເຕືອນ

ໜ້າ `/alerts` ຄິດການເຕືອນໃໝ່ຈາກຂໍ້ມູນປັດຈຸບັນທຸກຄັ້ງທີ່ເປີດ (ບໍ່ໄດ້ເກັບລົງຖານຂໍ້ມູນ)
ຈຶ່ງບໍ່ມີການເຕືອນເກົ່າຄ້າງຄາເມື່ອແກ້ຂໍ້ມູນແລ້ວ. ປັບເກນໄດ້ຢູ່ `/settings#alerts`:

| ການເຕືອນ | ເກນຕັ້ງຕົ້ນ |
|---|---|
| ໃຊ້ເກີນງົບຕໍ່ວັນ | ເກີນງົບ 10% |
| ງົບລວມ / ເພດານບັນຊີໃກ້ໝົດ | ໃຊ້ໄປ 80% |
| ROAS ຕ່ຳ (7 ວັນ) | ຕ່ຳກວ່າ 1.0x |
| ຄ່າຕໍ່ 1 ຄົນທັກສູງ | ປິດໄວ້ (ໃສ່ 0) |
| ລູກຄ້າຄ້າງສະຖານະ “ໃໝ່” | ເກີນ 3 ວັນ |
| ແຄມເປນໃກ້ຮອດວັນຈົບ | ພາຍໃນ 3 ວັນ |
| ຂໍ້ມູນຄ້າງ (ບໍ່ມີການດຶງສຳເລັດ) | ເກີນ 24 ຊົ່ວໂມງ |

ການເຕືອນ ROAS ກວດສະເພາະແຄມເປນເປົ້າໝາຍ **ຂໍ້ຄວາມ** ແລະ **ຍອດຂາຍ** —
ແຄມເປນປະເພດສ້າງການຮັບຮູ້ ຫຼື ເກັບລາຍຊື່ ບໍ່ໄດ້ຄາດຫວັງຍອດຂາຍໂດຍກົງ
ຈຶ່ງບໍ່ຖືກເຕືອນຜິດໆ.

### ສຸຂະພາບຂອງລະບົບເອງ (`src/lib/sync-health.ts`)

ນອກຈາກຜົນຂອງໂຄສະນາ ລະບົບຍັງເຕືອນເມື່ອ **ຕົວມັນເອງ** ເສຍ — ເພາະຕອນ token
ໝົດອາຍຸ ຫຼື ການດຶງລົ້ມ ໜ້າຈໍຈະ *ຍັງໂຊຕົວເລກເກົ່າຢູ່ຄືເກົ່າ* ແລ້ວຄົນເບິ່ງກໍ່ເຊື່ອ
ວ່າມັນຫຼ້າສຸດ ຈົນຕັດສິນໃຈໃຊ້ເງິນຈາກຂໍ້ມູນທີ່ຄ້າງມາຫຼາຍວັນ:

| ອາການ | ລະດັບ |
|---|---|
| token ໃຊ້ບໍ່ໄດ້ / ຖືກຍົກເລີກ | ດ່ວນຫຼາຍ |
| token ຈະໝົດອາຍຸໃນ ≤ 7 ວັນ | ລະວັງ (≤ 2 ວັນ = ຕ້ອງເບິ່ງ) |
| ຮອບດຶງຫຼ້າສຸດລົ້ມເຫຼວ | ຕ້ອງເບິ່ງ |
| ບໍ່ມີການດຶງສຳເລັດເກີນເກນ | ດ່ວນຫຼາຍ |
| ດຶງ comment / ແຊັດ ບໍ່ໄດ້ | ຕ້ອງເບິ່ງ |
| ວັນທີ່ໃຊ້ເງິນແຕ່ບໍ່ມີອັດຕາແລກປ່ຽນ | ລະວັງ (≥ 7 ວັນ = ຕ້ອງເບິ່ງ) |

ຫຼັກການສຳຄັນ: **ບອກຕົ້ນເຫດອັນດຽວ ບໍ່ແມ່ນຜົນທັງໝົດ** — ຖ້າ token ພັງແລ້ວ
ຈະບໍ່ໄປເຕືອນຊ້ຳວ່າ "ການດຶງລົ້ມ" ແລະ "ຂໍ້ມູນຄ້າງ" ອີກ ເພາະເປັນເລື່ອງດຽວກັນ
ແລະ ການເຕືອນສາມເທື່ອຄືກັນກັບບໍ່ໄດ້ເຕືອນ (ຄົນຈະຊິນແລ້ວເຊົາອ່ານ).

ອາຍຸ token ຖືກກວດເບື້ອງຫຼັງທຸກໆ 6 ຊົ່ວໂມງ ແລ້ວເກັບຜົນໄວ້ໃນ `AppSetting`
(`fbToken*`) — ໜ້າຈໍອ່ານຄ່າທີ່ເກັບໄວ້ ບໍ່ໄດ້ຮ້ອງ Facebook ຕອນເປີດໜ້າ.
ສະຖານະປັດຈຸບັນເບິ່ງໄດ້ຢູ່ `/settings`.

`/api/health` ບອກ `lastSyncAgeMinutes` ນຳ ເພື່ອໃຫ້ເຄື່ອງເຝົ້າເບິ່ງພາຍນອກ
ຮູ້ວ່າຂໍ້ມູນສົດປານໃດ ໂດຍບໍ່ຕ້ອງ login (route ນັ້ນຍັງບໍ່ສົ່ງຂໍ້ມູນທຸລະກິດອອກ).

## ຕໍ່ Facebook Marketing API (ທາງເລືອກ)

ຂັ້ນຕອນລະອຽດມີຢູ່ໃນແອັບແລ້ວ — ໜ້າ **ຕັ້ງຄ່າ** → “ເອົາ Access Token ຈາກໃສ?”
ສະຫຼຸບຄື:

1. **ຕ້ອງມີກ່ອນ:** ບັນຊີໂຄສະນາໃນ Ads Manager + [Business Manager](https://business.facebook.com)
2. **ສ້າງ App:** [developers.facebook.com/apps](https://developers.facebook.com/apps)
   → Create App → ປະເພດ **Business** → Add Product → **Marketing API**
3. **ເອົາ token (ແນະນຳ — ບໍ່ໝົດອາຍຸ):** Business Settings → Users → **System Users**
   → Add (ບົດບາດ Admin) → **Assign Assets** (ບັນຊີໂຄສະນາ + ເພຈ)
   → **Generate New Token** → ເລືອກ App → ຕິກສິດ `ads_read`
   *(ຢາກລອງໄວໆ: [Graph API Explorer](https://developers.facebook.com/tools/explorer)
   ໃຫ້ token ອາຍຸ 1–2 ຊົ່ວໂມງ)*
4. ໃສ່ access token ໃນໜ້າ **ຕັ້ງຄ່າ** → ກົດ **ບັນທຶກຄ່າ**
5. ກົດ **ທົດສອບການເຊື່ອມຕໍ່** → ລະບົບຈະສະແດງບັນຊີໂຄສະນາ ແລະ ເພຈ ທັງໝົດ
   ທີ່ token ນີ້ເຂົ້າເຖິງໄດ້ ພ້ອມ `act_...` ຂອງແຕ່ລະອັນ
6. ກົດ **ນຳເຂົ້າທັງໝົດ** → ຜູກ ID ໃສ່ບັນຊີ/ເພຈໃຫ້ອັດຕະໂນມັດ (ບໍ່ຕ້ອງພິມ `act_` ເອງ)
7. ຈາກນັ້ນຈຶ່ງກົດ **ດຶງຂໍ້ມູນດຽວນີ້** ເພື່ອດຶງແຄມເປນ ແລະ ຜົນລາຍວັນ

**App Review ຕ້ອງບໍ່?** ບໍ່ຕ້ອງ ຖ້າອ່ານສະເພາະບັນຊີຂອງຕົນເອງ — Standard Access
ທີ່ໄດ້ພ້ອມ Marketing API ພຽງພໍ (ຂີດຈຳກັດການເອີ້ນຕ່ຳກວ່າ ແຕ່ພໍສຳລັບດຶງຜົນລາຍວັນ).
ຈະຕ້ອງ Advanced Access ຜ່ານ App Review ກໍ່ຕໍ່ເມື່ອຈະດຶງບັນຊີຂອງລູກຄ້າຄົນອື່ນ.
4. ເລືອກຊ່ວງວັນ ແລະ ລະດັບທີ່ຢາກໄດ້ ແລ້ວກົດ “ດຶງຂໍ້ມູນດຽວນີ້”

ດຶງໄດ້ 3 ລະດັບ: **ແຄມເປນ** (ດຶງສະເໝີ), **ຊຸດໂຄສະນາ** ແລະ **ຊິ້ນໂຄສະນາ**
(ຕິກເພີ່ມເອົາ — ໄດ້ລາຍລະອຽດຫຼາຍກວ່າ ແຕ່ຊ້າ ແລະ ກິນໂຄຕ້າ API ຫຼາຍກວ່າ).
ລະບົບ upsert ໂຄງສ້າງຕາມ `fbCampaignId` / `fbAdSetId` / `fbAdId` ແລະ
ຜົນລາຍວັນຕາມ `(ວັນ, ອົງປະກອບ)` — ຂໍ້ມູນຈາກ API ຈະທັບຂອງທີ່ປ້ອນມືສະເພາະ
ວັນ/ອົງປະກອບດຽວກັນ. `targeting` ຂອງຊຸດຖືກຫຍໍ້ເປັນຂໍ້ຄວາມພາສາລາວໃຫ້ອ່ານງ່າຍ.
ຜົນການດຶງທຸກຄັ້ງ (ສຳເລັດ ຫຼື ຜິດພາດ) ຖືກບັນທຶກໄວ້ໃນ `SyncLog` ແລະ ສະແດງຢູ່ໜ້າຕັ້ງຄ່າ.

## ຂໍ້ຈຳກັດທີ່ຄວນຮູ້

- ຖ້າຈະເປີດອອກອິນເຕີເນັດ **ຕ້ອງແລ່ນຜ່ານ HTTPS** ແລ້ວຕັ້ງ `COOKIE_SECURE=1`
- ຍັງບໍ່ໄດ້ສ້າງບັນຊີຜູ້ໃຊ້ = ໃຊ້ລະຫັດຜ່ານດຽວຮ່ວມກັນ ຈຶ່ງບອກບໍ່ໄດ້ວ່າໃຜເປັນຄົນເຮັດ
  (ບັນທຶກການກະທຳຈະຂຽນວ່າ “ລະຫັດຜ່ານຮ່ວມ”). ສ້າງຜູ້ໃຊ້ຢູ່ `/settings#users` ເພື່ອແຍກຄົນ
- **ງົບຂອງແຄມເປນທີ່ຜູກ FB ຕັ້ງໄວ້ລະດັບຊຸດໂຄສະນາ (ບໍ່ແມ່ນ CBO)** ແກ້ຈາກລະບົບນີ້ບໍ່ໄດ້ —
  Facebook ຈະປະຕິເສດ ແລ້ວລະບົບຈະບອກເຫດຜົນ ໂດຍບໍ່ບັນທຶກຫຍັງ
- ນຳເຂົ້າຮັບແຕ່ **CSV** — ໄຟລ໌ `.xlsx` ຕ້ອງ Save As ເປັນ CSV ກ່ອນ
  (ລະບົບຈັບໄດ້ ແລະ ບອກວິທີໃຫ້)
- ການ sync ແລ່ນເບື້ອງຫຼັງ ແລະ ມີໄດ້ເທື່ອລະ 1 ວຽກ — ກົດຊ້ອນຈະຖືກປະຕິເສດ.
  ວຽກຢູ່ໃນໜ່ວຍຄວາມຈຳຂອງ process ຖ້າ restart ກາງຄັນ ວຽກຈະຖືກໝາຍເປັນ
  “ຜິດພາດ” ພາຍໃນ 15 ນາທີ ແລ້ວກົດດຶງໃໝ່ໄດ້ (ວັນທີ່ດຶງໄປແລ້ວບໍ່ຫາຍ).
- ການແຈ້ງເຕືອນຄິດສົດທຸກຄັ້ງທີ່ໂຫຼດໜ້າ (ລວມທັງເລກໃນເມນູ) — ຖ້າຂໍ້ມູນໃຫຍ່ຂຶ້ນຫຼາຍ
  ຄວນປ່ຽນເປັນ cache ຫຼື ຄິດເປັນຮອບ
